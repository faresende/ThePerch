# Insights + Health Integrations — Design

**Date:** 2026-04-26
**Status:** Approved scope; partial implementation in progress (this commit ships scaffolding + iOS surface; agents queue cred-required setup for user).

## Goal

Move The Perch from a passive **data display** to an **insight delivery** surface. The first concrete delivery: a daily writerly summary card on the Today tab, generated by BioChecha from the union of nutrition + workout + sleep + body-comp + spending + calendar data. Eventually expanding to multiple insight types (cross-domain, anomaly, negative-space, latency, spending-pattern).

## Architecture

```

│ public.orders + shipments (existing — commerce)            │

│ public.health_metrics    (NEW — sleep + body comp ingest)  │
└────────────────────────────────────────────────────────────┘
                            │

┌────────────────────────────────────────────────────────────┐

├────────────────────────────────────────────────────────────┤

└────────────────────────────────────────────────────────────┘
                            │
                            ▼
```

## Schema

### `public.health_metrics`

Single canonical table for sleep + body-composition data from any source. Uniform shape so BioChecha doesn't have to know which device produced what.

```sql
CREATE TABLE public.health_metrics (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id       uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  metric        text NOT NULL,        -- 'sleep_duration_min', 'hrv_rmssd_ms',
                                      -- 'sleep_score', 'weight_kg',
                                      -- 'body_fat_pct', 'bp_systolic', etc.
  value         numeric NOT NULL,
  unit          text,                 -- 'minutes', 'ms', 'kg', 'percent', 'mmHg'
  source        text NOT NULL,        -- '8sleep' | 'withings' | 'manual'
  source_id     text,                 -- vendor's record id (for dedup)
  measured_at   timestamptz NOT NULL, -- when the measurement happened
  ingested_at   timestamptz DEFAULT now(),
  details       jsonb,                -- extra context (sleep stages, etc.)
  UNIQUE (user_id, source, source_id, metric)
);
```

Indexes on `(user_id, metric, measured_at DESC)` for "last 7 days of sleep" queries.

### `public.insights`

```sql
CREATE TABLE public.insights (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id         uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  agent_id        text NOT NULL,       -- 'biochecha', 'claudinho', ...
  insight_type    text NOT NULL,       -- 'daily_health', 'cross_domain',
                                       -- 'spending_pattern', 'anomaly',
                                       -- 'negative_space', 'latency'
  title           text,                -- optional short headline
  body            text NOT NULL,       -- the writerly paragraph
  data            jsonb,               -- structured backing data
  source_refs     jsonb,               -- pointers to records that informed this
  generated_at    timestamptz NOT NULL DEFAULT now(),
  valid_for_date  date,                -- for daily insights, the day they cover
  shown_at        timestamptz,         -- first seen by user
  dismissed_at    timestamptz,
  pinned          boolean DEFAULT false,
  expires_at      timestamptz,
  created_at      timestamptz NOT NULL DEFAULT now(),
  updated_at      timestamptz NOT NULL DEFAULT now()
);
```

RLS owner-scoped. Indexes on `(user_id, valid_for_date DESC)` and `(user_id, pinned, generated_at DESC)`.

## iOS surface

### `DailyInsightCard` on Today tab

Lives near the top of the Today tab, after the greeting. Linen-aligned:

```
┌─────────────────────────────────────────────────────────┐
│ TODAY · BIOCHECHA                              7:14am   │
│                                                         │
│ Three short nights and HRV's been ducking. Lifting     │
│ hard while light on sleep is the part you've been      │
│ getting away with — until you don't. Today's a good    │
│ candidate for a recovery day; if not, drop the volume. │
│                                                         │
│ ▸ tap for sources                                       │
└─────────────────────────────────────────────────────────┘
```

- **Kicker**: `"TODAY · {agent_id.uppercased()}"`
- **Body**: serif italic, `palette.ink`, full text (no truncation when card is alone on top of feed)
- **Tap** → expands to show source data references (sleep nights summarized, workout volume, nutrition gap)

Empty state when no fresh insight: small muted line — "BioChecha takes the morning to read your data. Check back after 7am."

## Voice

Writerly, factual, slightly literary. Examples:

✅ "Three short nights and HRV's been ducking."
✅ "First Hardgraft order this year — last one was Apr 2025. Pattern's once-yearly so this is on cadence."
✅ "Heavier evening meals consistently precede shorter sleep. Last 4 of 5 cases."

❌ "You should sleep more!" (preachy)
❌ "Sleep duration: 6.4h, HRV: 51ms, ↓14% vs baseline" (data dump)
❌ "Your body is an amazing machine that deserves rest 💪" (woo)

Tone reference: BioChecha's IDENTITY.md — *"data-driven, no-BS, encouraging. Like a knowledgeable gym buddy who also happens to be a nutritionist. Direct, motivating, backed by data."*

## Ingestion paths

### 8sleep — direct API (preferred over HealthKit)

Reverse-engineered private API used by the Pod app:
- Auth: `POST https://api.8slp.net/v1/login` with email + password → JWT
- Sessions: `GET https://app-api.8slp.net/v1/users/me/intervals?from=...&to=...`
- Sleep stages: included in interval response
- HRV / RHR: `GET https://app-api.8slp.net/v2/users/me/trends`

Risk: 8sleep can change endpoints. We'll log everything to `agent_runs` so failures are visible immediately.

Credentials needed in `perch.env`:
```
EIGHT_SLEEP_EMAIL=fabio@example.com
EIGHT_SLEEP_PASSWORD=<password>
```

Stored in iCloud-synced `perch.env` (already set up, mode 600). Token cache lives in `~/.openclaw/state/8sleep-token.json`.

### Withings — public OAuth API

Public API at `https://wbsapi.withings.net`. Free tier covers personal use (well below 120 calls/min).

Setup (one-time, requires user):
1. Register a personal app at https://developer.withings.com/dashboard/
2. Set redirect URI to `http://localhost:8127/withings/callback` (a one-shot local server we spin up during the auth handshake)
3. Copy `client_id` + `client_secret` to `perch.env`:
   ```
   WITHINGS_CLIENT_ID=...
   WITHINGS_CLIENT_SECRET=...
   ```
4. Run `python3 ~/.openclaw/workspace/scripts/withings_setup.py` once — it will:
   - Open the auth URL in browser
   - Capture the redirect code on `localhost:8127`
   - Exchange for refresh + access tokens
   - Persist to `~/.openclaw/state/withings-tokens.json`
5. Hourly cron runs `withings_ingest.py` thereafter — refreshes token automatically.

### Cron schedule

Add to `~/.openclaw/cron/jobs.json`:

| Job | Schedule | Purpose |
|---|---|---|
| `8sleep-ingest` | every 30 min | pull last 24h of intervals + trends |
| `withings-ingest` | hourly | pull latest weight + BP measurements |
| `biochecha-daily-insight` | `0 7 * * *` Lisbon | generate the daily card |

## Hardening pass (gates public-repo flip)

Final checklist before flipping the GitHub repo to public:

1. **Secret scan** — gitleaks sweep across history. Anything caught requires a rewrite + force-push (separate decision).
2. **Supabase advisor** — re-run security + performance advisors, fix any new findings.
3. **RLS audit** — every table in `public.*` has owner-scoped policies; no service-role-only writes from client code.
4. **API key permissions** — service-role key never appears in iOS bundle. iOS uses anon key + RLS.
5. **README + docs cleanup** — replace `me@hellofabio.com`-specific examples, add a "this is a personal project" note.
6. **`.gitignore` review** — `.env`, `.env.*`, `secrets/`, `state/`, `*.sqlite`.
7. **LaunchAgent file permissions** — confirm scripts mode 700, secrets mode 600.
